## 🎁 v1.3.0 업데이트 내역

- **저장소를 SQLite로 통합**: 채널 목록, 녹화 이력, VOD 이력, 태그, 대기 알림이 각각 별도 JSON 파일에 흩어져 있던 것을 `data/signal_recorder.db` 하나로 합쳤습니다.
  - **기존 데이터는 첫 실행 때 자동으로 이관**됩니다. 원본 JSON은 삭제하지 않고 `.migrated` 접미사를 붙여 보관하므로 언제든 되돌릴 수 있습니다.
  - **녹화 종료가 빨라졌습니다**: 이전에는 이력을 저장할 때마다 전체 파일을 읽고 다시 썼기 때문에 이력이 쌓일수록 느려졌습니다. 이제 INSERT 한 번으로 끝납니다. 채널 설정 변경도 해당 항목만 UPDATE 합니다.
  - **WAL 모드**로 동작해 녹화 중 전원이 꺼져도 데이터가 깨지지 않습니다.
  - `sqlite3`는 Python 표준 라이브러리이므로 **단일 exe 크기나 리눅스 설치 방법에는 변화가 없습니다.**
- **라이브 감지 통계가 재시작 후에도 유지됩니다**: 이전에는 메모리에만 있어 앱을 껐다 켜면 통계 페이지의 감지 횟수가 초기화됐습니다.
- **실행 위치에 따라 데이터가 흩어지던 문제 해결**: VOD 이력과 태그가 상대 경로(`data/...`)를 사용해 프로그램을 어디서 실행했느냐에 따라 다른 파일을 읽던 결함을 바로잡았습니다.
- **태그 순서 유지**: 태그가 추가한 순서 그대로 표시됩니다.
- 개발 환경 정비: Python 버전을 **3.12.10**으로 고정(`backend/.python-version`)하고 테스트 의존성을 `requirements-dev.txt`로 분리했습니다. 저장소 구조는 `docs/storage.md`에 정리했습니다.

## 🎁 v1.2.0 업데이트 내역

- **Discord 알림 지연/누락 문제 근본 해결**: 알림 계층을 큐 기반 파이프라인으로 전면 재작성했습니다.
  - **유실 방지**: 봇이 재연결 중이거나 앱이 재시작되어도 알림을 버리지 않습니다. 미전송 알림은 디스크에 보관되었다가 연결 복구 후 이어서 전송됩니다. (기존에는 봇이 준비되지 않으면 로그조차 남기지 않고 조용히 폐기했습니다.)
  - **지연 제거**: 알림 전송을 감시 루프에서 분리했습니다. 이제 Discord 레이트 리밋에 걸려도 라이브 감지와 녹화 시작이 함께 밀리지 않습니다.
  - **감지 즉시 알림**: '방송 시작' 알림이 녹화 준비(CDN 대기 5초 + yt-dlp 기동)를 기다리지 않고 감지 시점에 바로 전송됩니다. 녹화 시작/완료는 별도 알림으로 이어집니다.
  - **긴 URL 유실 수정**: X Spaces Master URL처럼 1024자를 넘는 값이 Discord 크기 제한에 걸려 알림 전체가 실패하던 문제를 해결했습니다. 이제 여러 필드로 자동 분할되어 원본 그대로 전달됩니다.
  - **채널 조회 폴백**: 캐시에 없는 알림 채널(재연결 직후, 스레드 채널)을 REST API로 다시 조회합니다.
  - **재시도**: 레이트 리밋(429)과 일시적 서버 오류는 지수 백오프로 재시도하고, 권한 없음 같은 영구 실패만 포기합니다. 봇 재연결도 고정 30초에서 지수 백오프로 개선했습니다.
- **Webhook 폴백 지원**: `DISCORD_WEBHOOK_URL`을 설정하면 봇 연결이 죽어도 알림이 전달됩니다. 봇 없이 Webhook만 써도 동작합니다.
- **알림 종류별 ON/OFF 및 멘션**: 방송 감지, 녹화 시작/완료/실패, VOD 완료/실패, 쿠키 만료, 신규 버전 등 알림을 종류별로 켜고 끌 수 있습니다. 중요한 알림에만 `@here` 등 멘션을 붙이는 것도 가능합니다.
- **알림 진단 기능 추가**: Discord에서 `/diag`로 알림 큐 상태와 전송 채널 가용성을 확인하고, `/notify-test`로 테스트 알림을 보낼 수 있습니다. 설정 API에도 동일한 진단/테스트 엔드포인트를 추가했습니다.
- **VOD 이력 저장 경로 수정**: 상대 경로(`data/vod_history.json`)를 쓰던 탓에 실행 위치에 따라 다운로드 이력이 흩어지던 문제를 절대 경로로 고정해 해결했습니다.
- 새로운 런타임 의존성은 추가되지 않았습니다. (단일 exe 배포 및 리눅스 설치에 영향 없음)

## 🎁 v1.1.7 업데이트 내역

- **특수문자 및 쿼리가 포함된 채널 삭제 오류 수정**: 채널 ID나 URL에 슬래시(`/`) 혹은 쿼리 파라미터(`?v=...`)와 같은 특수문자가 들어간 잘못된 채널을 등록했을 때, 프론트엔드가 인코딩 없이 요청하여 쿼리 스트링 분리로 인해 감시 목록에서 정상 삭제되지 않던 치명적인 결함을 `encodeURIComponent` 처리를 통해 완벽히 해결했습니다.

## 🎁 v1.1.5 업데이트 내역

- **치지직 VOD ABR_HLS 다운로드 오류 수정 (KeyError)**: 치지직 다시보기 전송 방식 변경(ABR_HLS)으로 인해 VOD 다운로드 시 발생하던 `KeyError: 'sourceURL'` 및 `KeyError: 'media'` 결함을 yt-dlp 동적 멍키패치를 적용해 해결했습니다. 이제 최신 다시보기 영상부터 기존의 오래된 VOD까지 모두 정상적으로 즉시 다운로드 가능합니다.
- **VOD 처리 중 오판단 로직 제거**: 이전에 임시로 들어갔던 "1~2시간 대기 후 다시 시도" 빠른 실패 블록을 롤백(삭제)하여, 최신 VOD 감지 즉시 대기 없이 다운로드가 실행되도록 정상화했습니다.
