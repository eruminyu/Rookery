## 결정 기록

### 1. 프로젝트명을 `Signal-Recorder` → `Rookery`로 변경 (완료)

옛 이름은 두 가지가 문제였다. `Signal`이 메신저 앱과 충돌해 검색에서 묻히고,
`Recorder`가 기능의 일부만 설명한다(실제로는 VOD 다운로드·채팅 아카이브·통계·알림 포함).
표기도 `Signal-Recorder` / `signal-recorder` / `signal_recorder` / `Signal Recorder`
네 가지가 혼재했다.

`Rookery`는 떼까마귀의 집단 둥지다. 여러 채널을 한 화면에서 감시하는 대시보드 구조와
의미가 맞고, 한 단어라 표기 혼재가 구조적으로 사라진다.

후보였다가 버린 것:
- `Rook` — 짧고 좋았으나 체스 말로 먼저 읽힌다
- `Magpie` — 컨셉은 맞지만 마스코트 성격이 강해 다크 컨트롤룸 UI와 톤이 어긋난다
- `Amber` — 이름은 예쁘나 주황색이라 포인트 컬러 `#13d9a3`(민트)와 충돌
- `Squirrel` — 은유는 최적이나 이름이 전부 선점됨(Squirrel.Windows 등)

작업 내역과 마이그레이션 처리는 [`done-rename-rookery.md`](done-rename-rookery.md)에 있다.

### 2. 코드 식별자는 리네이밍하지 않는다

`channel`, `recording`, `vod_queue` 같은 도메인 용어를 `nest`, `catch`로 바꾸면
가독성만 나빠지고 diff가 수백 줄 나온다. 컨셉은 **사람이 읽는 표면**
(UI 카피, 로고, 문서, 봇 표시명)에만 반영한다.

같은 이유로 저장 폴더 `recordings/` → `roost/` 변경도 하지 않는다. 기존 사용자 경로가 깨진다.

### 3. Discord 봇은 각자 만들어 쓰는 방식(BYO)을 유지한다

개발자가 공용 봇을 호스팅하는 방안을 검토했으나 버렸다.

- **구조적으로 불가능에 가깝다.** 봇 프로세스가 사용자 백엔드 안에서 돈다.
  공용 봇으로 하려면 개발자 서버가 NAT 뒤의 각 사용자 인스턴스에 도달해야 하는데,
  릴레이 인프라를 세우는 순간 셀프호스트 툴이 SaaS 컨트롤 플레인이 된다.
  토큰을 배포해 각자 돌리게 하는 것도 안 된다 — 같은 토큰의 다중 게이트웨이 연결은 충돌하고,
  토큰이 공개되면 누구나 그 봇을 사칭할 수 있다.
- **이 봇은 알림 봇이 아니라 원격 제어기다.** 10개 명령이 전부 녹화기를 조작한다.
  제어권이 개발자 인프라를 경유하면 사고 한 번에 전 사용자 녹화가 멈춘다.
- **책임 주체가 바뀐다.** README에 "개인 소장 용도, 각자 약관 준수"라고 명시했는데,
  중앙 서비스를 운영하면 개발자가 운영 주체가 된다.

대신 **웹훅을 기본 알림 경로로 올린다.** 웹훅은 봇 생성 없이 채널 설정에서 URL만
복사하면 되고(30초), 대부분의 사용자는 이걸로 충분하다. 봇은 원격 제어를 원하는
사람만 쓰는 상위 옵션으로 둔다. 설정 화면도 이 순서로 재배치했다.

### 4. 봇 명령 권한 검사는 fail-closed

기존에는 호출자·채널 검증이 **전혀 없어서** 봇이 초대된 서버의 누구나 남의 녹화를
시작·중단할 수 있었다.

판정은 `_is_authorized()` 한 곳에서만 한다. 핸들러마다 `if`문을 넣으면 새 명령을
추가할 때 검사가 누락되기 때문에, `CommandTree.interaction_check`로 모든 슬래시
커맨드에 일괄 적용한다.

아무것도 설정되지 않았을 때 **열어두지 않고 거부한다.** 열어두면 위 사고가 그대로
재현되기 때문이다. `DISCORD_NOTIFICATION_CHANNEL_ID`가 있으면 그 채널을 조건으로 쓴다.

> **기존 사용자 영향**: 알림 채널 밖에서 명령을 쓰던 경우 거부된다. 릴리즈 노트 필요.

### 5. 프리픽스 명령을 버리고 슬래시 전용으로

10개 명령이 `!` 프리픽스와 슬래시로 완전히 중복 구현되어 있었다. 프리픽스 쪽 때문에
`message_content` intent가 필요했는데, 이는 개발자 포털에서 따로 켜야 하는
privileged intent라 봇 설정의 가장 큰 진입 장벽이었다.

공통 로직이 이미 헬퍼로 빠져 있어 프리픽스 핸들러를 지워도 잃는 기능이 없었다.
오히려 슬래시 쪽이 ephemeral 에러와 defer까지 갖춰 더 낫다.

빌트인 `!help`도 프리픽스 명령이라 `help_command=None`으로 껐다.
안 껐으면 권한 검사가 걸리지 않는 명령이 하나 남는다.

### 6. 설치·실행·업데이트 스크립트를 하나로 통합

8개로 흩어져 있었고 중복이 심했다. 색상 변수와 출력 헬퍼가 3벌,
`banner`·`detect_os`·`clone_repo`·`setup_dirs`·`print_done`이 2~3벌씩 있었다.

더 나빴던 것:
- systemd 유닛이 `install.sh`(일반 유닛)와 `setup_service.sh`(템플릿 유닛 `@`)로
  갈라져 서로 호환되지 않았고, `healthcheck.sh`는 일반 유닛만 확인했다
- 네이티브 설치에는 **업데이트 스크립트가 아예 없었다**

`manage.sh` 하나로 합쳤다. 원라이너가 설치와 업데이트를 겸하고, 설치 후에는
`rookery` 명령으로 전부 처리한다. `curl | bash`로 실행되므로 자기완결적으로
두고, 상세 점검만 `healthcheck.sh`에 위임한다(중복이 아니라 고유 로직이라 남겼다).

**Docker는 대상에서 제외했다.** compose로 직접 띄우는 편이 단순하고, Docker Engine
설치까지 스크립트가 떠안을 이유가 없다. `docker-compose.yml`과
[`docker-guide.md`](docker-guide.md)는 그대로다.

### 7. `.gitattributes`로 줄바꿈 고정

셸 스크립트가 CRLF로 체크아웃되면 셔뱅이 `bash\r`로 읽혀 **원라이너 설치가 통째로
실패한다.** 반대로 배치 파일이 LF면 cmd.exe가 라벨을 파싱하지 못한다(실제로 겪었다).

`*.sh`는 LF, `*.bat`/`*.cmd`/`*.ps1`은 CRLF로 고정했다.
**전역 정규화(`* text=auto`)는 하지 않았다** — 저장소 대부분이 CRLF라 diff가 통째로
부풀어 리뷰가 불가능해진다.

## 새 기기 셋업

```bash
git clone -b refactor/notification-pipeline https://github.com/eruminyu/Signal-Recorder.git
cd Signal-Recorder
```

- Linux / macOS: `bash scripts/manage.sh install`
- Windows: `scripts\manage.bat install`

저장소 안에서 실행하면 그 경로를 설치 위치로 잡으므로 별도 클론이 생기지 않는다.

`.env`는 git에 없다. 새로 설정하면 첫 실행 시 브라우저에 **초기 설정 마법사**가 떠서
저장 경로·화질·라이브 포맷을 UI에서 잡을 수 있다. 다만 아래는 수동으로 다시 넣어야 한다.

- 치지직 인증 쿠키 (연령 제한·고화질용, 없어도 일반 방송은 녹화됨)
- X Spaces 쿠키 파일 (Netscape 형식)
- TwitCasting Client ID / Secret
- Discord 봇 토큰 또는 웹훅 URL, 알림 채널 ID

`backend/data/*.db`도 git에 없다. 안 옮기면 채널 목록과 녹화 이력이 비어 있는 상태로
시작한다(기능 문제는 없다).

## 알아두면 좋은 함정

- **샌드박스에서 pytest가 무더기 `PermissionError`로 죽는 경우** — 코드 문제가 아니라
  `conftest.py`가 쓰는 임시 디렉토리 권한 문제다. `--basetemp=<쓰기 가능한 경로>`로 우회한다.
- **`git add --renormalize .` 를 쓰지 말 것.** `.gitattributes`와 무관하게 저장소 전체를
  재정규화해서, 건드리지도 않은 파일 50여 개가 줄바꿈만 바뀐 채 staged 된다.
- **셸에 node가 PATH에 없을 수 있다.** `C:\Program Files\nodejs`를 직접 잡아야 한다.
- **`_build_bot`은 동기 함수다** (`main` 브랜치에서는 async였다). 테스트에서 await하지 말 것.
- `*.spec`(PyInstaller)은 gitignore 대상이라 저장소에 없다. `Rookery.exe` 산출물명 변경은
  빌드 머신에서 직접 처리해야 한다.
- `backend/app/static/`은 빌드 산출물이자 gitignore 대상이다. 프론트엔드를 빌드해야 웹 UI가 뜬다.
